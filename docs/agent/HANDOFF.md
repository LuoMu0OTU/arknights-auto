## 问题 1（✅ 已修复 2026-11-02，commit `5223a9e`）：基建铃铛点不开待办条

### 根因（已定位，不是猜测）
CustomAction 里 `ctrl.cached_image` 返回的是**本节点识别时**那张旧帧，**点击后不刷新**。
所以点完铃铛去看待办条，看到的永远是点击前的画面 → 判定"没打开" → 补点第二个位置；
`InfrastTodoCollect` 同样看旧帧 → 识别不到按钮 → 报「待办事项已点完」**假成功**。

（本文档下面"待查方向"里的第 1、2、3、4 条都是当时没定位时的猜测，**已经被根因否定**：
点击能落到游戏、2.2 秒足够、OCR 有效、按钮能读出来——唯一错的是取图方式。）

### 修复
- `fresh_image(ctrl)`：每次判断前主动 `post_screencap` 抓新帧。
- 判据改为 OCR 左下角「待办事项」标签（`bar_opened`），不再用"有没有按钮"。
- `pick_target` / `todo_names_in` 纯函数；同名按钮最多重点 3 次，点满仍在则**如实失败**。
- 真机验证：`点铃铛#1 → 待办条已打开 → 点「订单交付」→ 点「干员休整」→ 清空`，Infrast 两轮 112 秒 OK。

### 现象存档（修复前负责人真机复现 4 次）
```

[infrast] 点铃铛 #2 (1242,133)
[infrast] 铃铛两次点击后仍未打开待办条   ← 其实已经开了，是旧帧没看见
[infrast] 待办事项已点完（连续 2 次确认） ← 假成功
```

### 仍未做
